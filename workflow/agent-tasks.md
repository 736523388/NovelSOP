# Agent 任务卡

按当前步骤选择一张任务卡。开始时读取 [总约定](README.md)，再读对应流程。以下内容可复制给 Agent，尖括号替换为具体路径与章号。

## 策划：选题与开书

```text
项目：books/<项目代号>/
执行 workflow/01-start.md 当前阶段，先读取 project.md 和 control.md。
检索近期同类作品及官方资料；每项观察记录来源、日期、实际阅读范围。
区分市场事实、创作判断、作者偏好和待核实事项。
交付三个可比较方案：目标读者、卖点、主角欲望、阻力、持续冲突、差异点、成本。
推荐一个并说明理由，把需作者选择的内容集中列出。
将结果保存到 project.md；未选定方案保留为候选。
完成条件按当前阶段执行，不提前将候选设定写入正式账本。
```

## 策划：准备下一章

```text
项目：<路径>；目标章：<N>。
执行 workflow/02-chapter.md 第1—2步。
读取最新归档状态、卷目标、承诺账本、上一章结尾和相关历史证据。
填写本章 work.md：人物目标—阻力—选择—代价—结果，说明读者获得什么。
明确人物所知、读者所知、不可提前揭示的信息及需推进的伏笔。
关键事实缺失时检索原文；无法确定的列为待决，不补造历史。
交付章卡、上下文来源清单和必要的备选方案。
```

## 写作：完成当前章

```text
项目：<路径>；章节工作包：<路径>；当前正文版本：<文件或待创建>。
执行 workflow/02-chapter.md 第3步，以已确认章卡和相关事实为输入。
写出完整正文，保持项目的视角和作者认可的声音。
用人物行动和具体后果兑现章卡，合理分配场景篇幅。
把新增设定候选、需要核实的细节、偏离章卡之处单独写入工作包。
只修改本章草稿和工作记录，正式状态由归档步骤提交。
交付正文文件、版本与偏离说明。
```

## 审校：连续性

```text
审查 <正文文件及版本>，读取其章卡、当前账本和有关终稿原文。
按 workflow/02-chapter.md 第4步的分级检查时间、地点、人物动机、
能力代价、物品资源、人物知情、事件因果、视角与伏笔。
每条意见提供：正文位置、冲突依据、严重度、影响、最小修法。
区分事实错误、可能有意的叙事设计和信息不足；信息不足标为待核实。
给出已核查范围及未核查范围。可以没有问题，不凑数量。
输出到工作包审校区，注明输入版本；不直接修改正文与账本。
```

## 审校：阅读体验

```text
审查 <正文文件及版本>，读取目标读者、阅读承诺、章卡和作者样章。
定位会影响理解或继续阅读的具体段落：动机不明、回报延迟、
重复解释、机械描写、对白趋同、无效转折或没有兑现的悬念。
日常、慢节奏章节按关系与情绪变化评价，不强制每章反转或打脸。
按 A/B/C 分级给出位置、阅读影响和最小修法；审美偏好明确标为建议。
这是编辑判断，不输出预计真实追读率、平台通过概率或伪造试读结果。
交付问题表与值得保留的关键段落，写入工作包。
```

## 写作：定向修订

```text
读取 <当前正文>、工作包中的问题表及作者已经作出的决定。
按 workflow/02-chapter.md 第5步处理问题，保存新版本。
先处理 A，再处理 B；C 只采用与作者风格一致且有明确收益的建议。
标记每条意见为已修复、作者保留、待核实或需决策，并说明依据。
检查修改对相邻场景、事实及伏笔的影响，再提交对应范围复核。
达到本轮修订上限仍有关键冲突时，给出具体备选供作者裁决。
```

## 记录：终稿归档

```text
作者已确认 <终稿文件及版本>；确认依据见 <记录位置>。
执行 workflow/02-chapter.md 第7—8步。
从该终稿提取事实变化，逐条引用场景或段落；未来计划留在计划区。
用唯一归档编号核对候选变化，保留账本更新前快照，再逐项写入。
验证人物状态、知情、资源、伏笔与承诺，最后更新 control.md。
已有相同归档编号时先核对是否完成，补齐遗漏，不重复计数。
交付归档编号、账本前后版本、变化清单和下一章承接点。
```

## 复盘：连载或试写

```text
项目：<路径>；观察范围：<章号与日期>。
执行 workflow/04-review.md，读取真实数据、读者评论、正文和决策记录。
先列已知事实、指标口径与样本缺口，再提出问题假设。
交付一项优先调整方案：证据、原因假设、改动位置、预期观察、复查时间、回退方式。
同时记录作者修改时间和流程问题。数据不足时说明不能判断的结论。
变更进入 control.md；涉及主线或结局时提出方案供作者决定。
```

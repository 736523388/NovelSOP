# 连载复盘与每日运行

使用 [工作台模板](templates/control.md) 记录真实数据与决定。目的：找出影响阅读或生产稳定性的具体问题，调整下一情节段。

## 每日循环

1. 开工：读工作台，处理归档失败和未决关键事实，明确今天的定稿及发布任务。
2. 写作：按 [章节流程](02-chapter.md) 完成当前章；按可投入时间安排产出，不按模型吐字速度计划更新。
3. 发布：核查当天材料与授权，登记实际审核及发布状态。
4. 收工：记录已完成文件、最新账本版本、未决问题和下一步；更新缓冲稿覆盖天数。

缓冲稿覆盖天数 = 可发布终稿字数 ÷ 计划日更字数。草稿、待审稿不计入可发布库存；日更计划未定时保留空值。

完成条件：下一次可从工作台直接恢复；今日任务未完成时写出真实进度及原因。

## 复盘触发

- 每周做一次轻量复盘。
- 每个主要情节段结束后检查回报、人物变化和新期待。
- 某章出现明显流失、重复读者投诉或平台反馈时做定点复盘。
- 每卷结束或完结前，按平台节点做承诺与悬线清算。

周与情节段复盘可以合并，避免重复工作。

## 复盘步骤

### 1. 固定观察范围

记录日期窗口、章号、发布版本、作品所处阶段、数据来源、指标定义和样本量。记录同期是否换书名、改简介、集中更新或修改旧章。

只有公开榜单或阅读热度时，不推算后台追读率；无真实反馈时，只做文本与产能复盘。

### 2. 定位问题

| 现象 | 优先核查 | 可尝试的动作 |
|---|---|---|
| 展示少 | 资格、阶段、系统消息和样本 | 先核对平台状态 |
| 展示后少人阅读 | 包装与受众、承诺清晰度 | 修改一项主要包装因素并记录 |
| 开篇掉读 | 人物目标、卖点兑现、背景负担 | 修订具体场景或信息顺序 |
| 某章掉读 | 前后章情绪、重复、人物选择 | 回读相邻章节后定点修复 |
| 读完但少追更 | 主角牵引、后续目标、期待 | 调整下一情节段承诺 |
| 返工时间持续增加 | 章卡不清、上下文缺失、规则冲突 | 修输入或记忆步骤 |

现象只支持提出假设。数据人数、时间窗口或人群不一致时，先解释差异，不直接下因果结论。

### 3. 作出小范围调整

每次挑选一项主要问题，写出证据、假设、方案、预期可观察变化、复查时间及回退方式。优先调整近期场景与节奏；改核心人物、主线、结局需作者裁决。

模型意见与真实读者反馈分栏。评论按问题聚类，标明代表性和数量；少量意见用于提出问题，不能冒充全体读者意愿。

### 4. 核对结果

复查同定义指标与文本表现，同时记录样本变化。数据不足写“暂不能判断”，允许保留方案继续观察或回退。完成后更新决策记录与下一情节段计划。

## 试运行验收

连续试写后比较：作者修改用时、A 类问题数、修订轮数、终稿可用程度、人物声音、真实试读反馈、模型费用。以作者时间和实际质量决定是否增加自动化。

不要求所有问题降为零；要求重大矛盾被处理、流程可恢复、作者愿意继续使用，并能说明最需要改进的一个环节。
